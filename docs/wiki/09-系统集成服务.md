# 09 · 系统集成服务

[← 返回首页](Home.md) · 源码：Memozia/Services/

本篇覆盖与操作系统深度集成的辅助服务：菜单栏、全局热键、AppKit 桥接工具。

## 1. MenuBarController — 菜单栏控制器

源码：[MenuBarController.swift](../../Memozia/Services/MenuBarController.swift)（`@MainActor` 单例）

### 1.1 职责

macOS 菜单栏常驻控制中心（`NSStatusBar.system.statusItem`），在主窗口隐藏/共享屏幕场景下提供全部功能入口。

### 1.2 菜单结构（`start()`）

| 菜单项 | 动作 |
|--------|------|
| 开始录音 / 停止录音 | `menuBarStartRecording` / `menuBarStopRecording` 通知 → RootView → RecordingViewModel；录屏进行中状态项显示「录屏中」、切换项显示「停止录制」（依据 `MeetingRecorderService.isScreenRecording`，音频 + 视频轨共用同一停止链路） |
| 捕获屏幕（子菜单，原「截图」+「录屏」两项合并） | 截图组：新建区域截图（⌥⌘S）/截取窗口/截取全屏 → `menuBarStartScreenshot`（带 mode），进统一捕获会话（会话工具栏含「录制」出口）；录屏组：录全屏（鼠标所在屏）一步直达，录选区/录窗口 → `menuBarStartScreenRecording`（带 target），路由到带录制出口的捕获会话（intent=record，选定目标后自动 3 秒倒计时）；尾部声源/质量 radio 为独立偏好 `screen_recording_source/quality`（与设置页「捕获」节同键），不影响会议录音设置 |
| 麦克风（子菜单，与「捕获屏幕」同级、紧随其下） | 列系统全部输入设备（`MicrophoneDeviceRegistry`，含虚拟/回环设备，勾选当前项，已选设备拔出时占位提示）；与设置页「录音 → 输入设备」、截图会话工具栏 mic 按钮、录音中状态徽章的麦克风菜单共用同一偏好 `microphone_device_uid`。会议录音与录屏都用它，故不再放在「捕获屏幕」子菜单内。子菜单另含录制中的「静音麦克风 / 解除静音」与空闲时预设下一场录音的「录音开始时静音麦克风」勾选项（与录音状态徽章、截图会话工具栏共用 `MicrophoneStartMutePreference`） |
| 隐藏主窗口 | `NSApp.setActivationPolicy(.accessory)`（隐藏 Dock 图标+主窗，仅留菜单栏——共享屏幕场景） |
| 从剪贴板新建笔记 | `menuBarCreateQuickNoteFromClipboard` → QuickNoteViewModel.createQuickNoteFromClipboard（该命令实际创建的是快捷笔记，名称已由 `AppCommandCatalog` 统一为「从剪贴板新建笔记」） |
| 切换语言（子菜单） | `applyInterfaceLanguage(code)`：写 AppleLanguages + 弹重启询问 |
| 设置 | `menuBarOpenSettings` 通知 |
| 退出 | 录音中先走**统一停止入口**：菜单栏只发 `menuBarStopRecording`，等 ViewModel 收尾完成回发的 `menuBarStopRecordingCompleted`（并以「服务已停且合并不进行中」兜底、900s 上限）再 `NSApp.terminate`；旧实现先直接调服务的 `stopRecording()`，停止通知随后被 `guard isMeetingRecording` 拦下，封存/合并/入库整段被跳过（文件已生成但本次没有数据库条目）。常规退出走 `applicationShouldTerminate` 收尾链，收尾完成后 `_exit` 结束进程以跳过 onnxruntime 静态析构崩溃 |

命令的**名称与快捷键**不在这里各自硬编码：菜单栏、应用菜单（`MemoziaApp.commands`）、帮助页「快捷键」小节与设置搜索统一引用 `AppCommandCatalog`（`AppCommandDescriptor`：id / `titleKey` / `CommandShortcut` / `settingsDestination`）。全局热键类命令的显示值实时读 `GlobalHotkeyManager`，用户改完热键后各处立刻同步。

### 1.3 窗口管理

| 方法 | 职责 |
|------|------|
| `showMainWindow()` | 取消待完成的隐藏请求，幂等恢复主窗口：makeKeyAndOrderFront + deminiaturize 最小化窗口；维护 `mainWindows` 列表 |
| `hideMainWindow()` | 通过 `HideOnCloseWindowDelegate` 先退出全屏 Space 再隐藏；全部窗口完成后才切 accessory 隐藏 Dock |
| `applyInterfaceLanguage(_:)` | 语言切换：空 = 跟随系统（清 AppleLanguages）；写偏好后询问重启 |
| `availableLanguages` | 语言清单见源码与本地化资源，菜单显示各语言自称 |

状态图标：使用 [MemoziaMenuBar.symbolset](../../Memozia/Resources/Assets.xcassets/MemoziaMenuBar.symbolset) 中的自定义 SF Symbol（03「折角纸页 + 声波」的单色线稿，Regular 字重，提供 Small / Medium / Large 三种比例），以 18pt 单色模板显示。`MenuBarController.menuBarImage` 缓存图像，`isTemplate = true` 让系统适配深浅色、高亮与对比度；资源缺失时记录错误并回退到系统波形图标。录音状态由菜单项文本表达（录音中／录屏中／静音），录屏时切换项显示「停止录制」。PRD 的 FR-12.1 仍写着随状态切换图标形态，与当前固定图标的实现有差异，本次保留现有状态表达方式。

### 1.4 Dock 图标显隐

`NSApp.setActivationPolicy(.regular / .accessory)` 切换；配合 AppDelegate 的 reopen/becomeActive 兜底（见 [02-整体架构](02-整体架构.md) §3）实现"点 Dock 图标即可恢复"。

红色关闭按钮仍只隐藏窗口。全屏时不能直接 `orderOut`，否则会留下没有窗口的黑色全屏 Space；`HideOnCloseWindowDelegate` 等待进入/退出全屏动画完成，在 `windowDidExitFullScreen` 后的主队列下一轮隐藏，并继续转发 SwiftUI 原委托回调。恢复窗口会取消待隐藏请求；退出全屏失败时保留窗口并记录错误，允许重试。

## 2. GlobalHotkeyManager — 全局热键

源码：[GlobalHotkeyManager.swift](../../Memozia/Services/GlobalHotkeyManager.swift)（`@MainActor` 单例）

### 2.1 技术方案

**Carbon `RegisterEventHotKey`**（应用未激活时也可触发，这是 Carbon API 在现代 macOS 上仍不可替代的场景）。

### 2.2 默认热键

| 热键 | 功能 | 生效范围 |
|------|------|----------|
| `⌃⌘R` | 会议录音开/停切换 | 两种模式 |
| `⌃⌘S` | 区域截图（按默认模式） | 两种模式 |
| `⌃⌘W` | 全屏直拍 | 仅专业模式注册 |

热键组合可配置（UserDefaults 持久化），`start()`启动时加载配置并注册，记录生效组合。设置入口是独立的「设置 → 热键」页（`HotkeySettingsView`），两种模式均可见；该页在普通模式隐藏「全屏直拍热键」一行（对应组合在普通模式本就不注册）。

**录音热键冲突回退**：`⌃⌘R` 被其他应用占用（`RegisterEventHotKey` 返回非 `noErr`）时自动改用备选组合 `⇧⌃⌘R`。回退只针对「当前组合仍是默认值」的情形（判定见纯函数 `recordingFallbackCombination`）——用户显式改过的组合若注册失败就如实报失败，不会被悄悄替换。回退结果只存在内存（`recordingHotkeyFellBack`，设置页据此说明原因），不写入 UserDefaults：持久化的是**用户意图**，因此占用方消失后下次启动会自动回到 `⌃⌘R`。

配置约束（`updateHotkey` / `updateFullscreenHotkey` / `updateRecordingHotkey` 返回具体失败原因，设置页据此提示）：

- 非功能键必须至少带一个修饰键；**F1–F20 可单独使用**（此类组合修饰键为 0，`loadFromDefaults` 以「任一项非 0」判定是否已配置）
- 拒绝应用内重复组合（三条热键两两不得相同，统一由 `isDuplicateOfOtherHotkey` 判定）
- 拒绝系统保留组合 `⌃⌘F`（Cocoa 标准菜单「进入全屏幕」）

注册与失败可见性：三条热键**逐条注册**，单条失败只影响该条（不整体回滚）；失败的热键记入 `unregisteredHotkeys`（error 级日志 + 设置页「热键」页提示），避免旧实现「一条被占用即全部失效且界面无提示」。

### 2.4 事件分发

注册 `EventHandler` → 回调按热键 ID 分发 `NotificationCenter` 通知：

- `.recordingHotkeyPressed` → RootView `toggleMeetingRecording()`（与工具栏「录音」按钮同一动作）
- `.screenshotHotkeyPressed` → RootView 读取 `screenshotDefaultMode` → `ScreenshotManager.startCapture(mode:)`
- `.fullscreenScreenshotHotkeyPressed` → `ScreenshotManager.captureFullScreenDirect()`

注销/重注册：设置变更后先 unregister 再 register。

## 3. MainActor+AssumeOnMainThread — AppKit 桥接工具

源码：[MainActor+AssumeOnMainThread.swift](../../Memozia/Services/MainActor+AssumeOnMainThread.swift)

```swift
extension MainActor {
    /// AppKit 同步回调中安全进入 MainActor
    static func assumeOnMainThread(_ body: @MainActor () -> Void)
}
```

**解决的问题**：AppKit 同步回调（`applicationDidFinishLaunching` 等，无 Task 上下文）直接用 `MainActor.assumeIsolated` 在 macOS 26 上可能触发 executor 断言崩溃；此工具只做主线程检查后直接进入 MainActor 上下文。全项目 AppDelegate 回调统一使用。

## 4. RemindersURLDiagnostic — 提醒事项 URL 诊断

源码：[RemindersURLDiagnostic.swift](../../Memozia/Services/RemindersURLDiagnostic.swift)

一次性诊断工具（详见 [06-LLM总结与智能功能](06-LLM总结与智能功能.md) §4）：`reminders_url_diagnostic` defaults 标记触发，验证 EKReminder 的 URL 字段写入行为，结果写 `~/Documents/Memozia/url_diagnostic.txt`，完成后自动清除标记。

## 5. 系统权限总表

| 权限 | 用途 | 授权方式 |
|------|------|----------|
| 麦克风（NSMicrophoneUsageDescription） | 会议录音 | TCC 弹窗 |
| 语音识别（NSSpeechRecognitionUsageDescription） | 系统语音转写（macOS 26+） | 按功能请求 TCC 授权 |
| 屏幕录制 | 系统音频采集（SCStream）+ 截图（SCScreenshotManager） | 系统设置，**授权后需重启应用** |
| 辅助功能（Accessibility） | AppMuteDetector AX 树轮询 | 系统设置 |
| 提醒事项（NSRemindersUsageDescription） | 待办写入 EKReminder | TCC 弹窗 |
| 网络客户端（entitlements） | 云端 API / 模型下载 | entitlements |
| 用户选择文件读写（entitlements） | 导入音频/导出文档 | entitlements |

macOS entitlements（[Memozia.entitlements](../../Memozia/Resources/Memozia.entitlements)）遵循最小权限：`audio-input` + `network.client` + `files.user-selected.read-write`，**未启用** App Sandbox（直写 ~/Documents 需要），**未启用** `cs.disable-library-validation`（安全考量）。工程已取消 iOS 支持，原 iOS 分享扩展的 App Group entitlement 已随扩展删除。

## 6. 应用更新

源码：[AppUpdateService.swift](../../Memozia/Services/AppUpdateService.swift)、[UpdateInstallationCoordinator.swift](../../Memozia/Services/UpdateInstallationCoordinator.swift)、[UpdatePermissionRepair.swift](../../Memozia/Services/UpdatePermissionRepair.swift)。

- Sparkle 更新器只在主应用已获隐私同意并取得持久化容器后启动；worker、单元测试和 UI 测试不启动更新器。
- 当前副本未配置更新源与公钥，更新器不会启动，菜单和「设置 → 关于」隐藏检查入口。配置可信更新源后，自动检查仍默认关闭，安装仍需确认。
- 安装前检查录音、录屏、截图、导入、磁盘对账及处理任务资源，保存 ModelContext、停止旧 worker 并等待 `EntryMirrorStore.flush()`；异步等待后再次检查空闲。失败会取消退出并提示稍后重试。
- 更新退出不会拉起旧 worker，新版按既有启动协议接管；退出仍使用 `_exit` 规避 ONNX 静态析构。
- 独立发布时只配置 stable 更新频道；当前副本未建立任何更新频道。
- 按用户要求，明确标记为未公证更新包的临时签名版本，首次持久化主应用启动会清理本应用旧 TCC 授权。`UpdatePermissionRepair` 用实际代码签名哈希和构建号去重，只执行固定的 `tccutil reset All app.memozia`；首次安装建立基线，稳定签名和同一代码身份重启不重复清理。开发调试构建、worker、测试、临时模式或仍有采集资源时不执行。5 秒超时/取消会结束子进程，失败不标为成功并显示提示。
- `StartupRootView` 在主界面开放前等待授权修复；隐私同意后启动任务链及录音/捕获入口复用同一执行体。清理后仍由系统弹窗征求授权，不用历史标记冒充已授权。正常退出等待修复收尾，更新安装也检查该资源。定向测试不执行真实 TCC 重置。
- 完整的两版本替换、重启与权限连续性需要实际升级验收；构建与单元测试不能替代这一步。发布前配置与验收见 [发布检查](../RELEASE_CHECKLIST.md)。
